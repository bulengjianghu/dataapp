# 组件配置项解藕

## 1. 目标（二维表）
| 目标 | 说明 |
|---|---|
| 按组件动态展示配置项 | 选中不同组件时，属性面板自动切换对应配置项 |
| 配置项与组件解耦 | 属性面板不写死组件逻辑，通过配置元数据驱动 |
| 易扩展 | 新增组件时只需注册配置，不改PropertyPanel主流程 |

## 2. 核心思路（二维表）
| 设计点 | 方案 | 价值 |
|---|---|---|
| 选中态来源 | Store中维护 `selectedFieldKey`，selector解析当前 `component` | 状态单一、链路清晰 |
| 配置来源 | `componentConfigRegistry` 注册中心 | UI与业务组件解耦 |
| 面板渲染 | PropertyPanel根据 `propertySchema` 动态渲染控件 | 减少分支判断与重复代码 |
| 数据写回 | 统一 `updateFieldProps` reducer 合并patch | 更新路径一致、便于审计 |

## 3. 选中不同组件时的展示流程（二维表）
| 步骤 | 输入 | 处理 | 输出 |
|---|---|---|---|
| 1 | 用户在画布选中组件 | dispatch `selectField(fieldKey)` | 更新 `selectedFieldKey` |
| 2 | PropertyPanel读取selector | 获取 `selectedField.component` | 得到组件类型 |
| 3 | 查询注册表 | 按组件类型读取 `propertySchema` | 得到可配置项定义 |
| 4 | 动态渲染 | 渲染基础/校验/布局/高级分组配置 | 展示对应配置UI |
| 5 | 用户修改配置 | 生成 `patch` | dispatch `updateFieldProps` 写回schema |

## 4. 配置注册表设计（二维表）
| 项 | 说明 | 示例 |
|---|---|---|
| `component` | 组件类型标识 | `input` / `number` / `select` / `container` |
| `propertySchema` | 属性项元数据数组 | 字段、控件类型、分组、显示条件 |
| `defaults` | 默认配置 | placeholder、required、span等 |
| `capabilities`（可选） | 能力声明 | 支持校验/支持默认值/支持布局 |

示例类型定义：
```ts
type PropertySchemaItem = {
  key: string;
  label: string;
  control: 'input' | 'switch' | 'select' | 'number';
  group: 'basic' | 'validation' | 'layout' | 'advanced';
  visibleWhen?: (field: any) => boolean;
  normalize?: (value: any) => any;
};

type ComponentConfig = {
  component: string;
  propertySchema: PropertySchemaItem[];
  defaults: Record<string, any>;
  capabilities?: {
    supportsValidation?: boolean;
    supportsLayout?: boolean;
    supportsDefaultValue?: boolean;
  };
};
```

## 5. PropertyPanel解藕实现（二维表）
| 层次 | 责任 | 约束 |
|---|---|---|
| PropertyPanel容器 | 读取选中字段、查注册表、组织分组 | 不包含具体组件业务分支 |
| PropertyRenderer | 按 `control` 渲染控件（Input/Switch/Select等） | 只消费schema，不依赖组件类型 |
| ValueAdapter | 处理 `normalize/deserialize` 值映射 | 防止UI值与存储值耦合 |
| Reducer | 合并patch、标记dirty | 不关心面板控件细节 |

## 6. 配置项分层复用（二维表）
| 分层 | 内容 | 复用方式 |
|---|---|---|
| 通用配置 | 标题、字段标识、必填、布局span | 抽成共享schema片段 |
| 组件专属配置 | 如select的options、upload的limit | 在注册表中按组件追加 |
| 扩展配置 | 高级参数/实验开关 | 通过capabilities控制显示 |

## 7. Store更新链路（二维表）
| 动作 | 触发点 | Reducer处理 |
|---|---|---|
| `selectField` | 点击组件 | 设置 `selectedFieldKey` |
| `updateFieldProps` | 修改任意属性项 | 合并patch到目标字段，`dirty=true` |
| `resetDraft` | 撤销未保存改动 | 恢复到上次草稿快照 |

## 8. 解藕收益（二维表）
| 收益 | 说明 |
|---|---|
| 可维护性 | 新增组件只需注册配置，不改核心面板逻辑 |
| 一致性 | 所有属性改动都走统一action与reducer |
| 审核友好 | action链路清晰，便于AI开发+人工Code Review |
| 扩展性 | 后续接入复杂组件/规则时改动范围可控 |

## 9. 实施建议（二维表）
| 步骤 | 内容 | 产出 |
|---|---|---|
| Step 1 | 建立 `componentConfigRegistry` | 组件配置注册中心 |
| Step 2 | 抽象 `PropertyRenderer` | 通用属性渲染器 |
| Step 3 | 接入 `updateFieldProps` 统一写回 | 统一状态更新链路 |
| Step 4 | 迁移现有组件配置到注册表 | 减少硬编码分支 |
| Step 5 | 补齐单测/快照测试 | 保证配置渲染稳定 |
