# 文档总览

## 结构说明

`docs` 目录按“需求 -> 设计 -> 开发 -> 规范”组织，分别回答以下问题：

- `需求`：做什么，为什么做，如何验收
- `设计`：怎么设计，为什么这样设计，关键取舍是什么
- `开发`：怎么实施，如何拆分任务，如何推进和验收
- `规范`：跨阶段长期有效的协作约束

## 按角色阅读

- 产品/需求分析：先读 [需求梳理.md](./需求/需求梳理.md)，再进入对应阶段需求
- 架构/后端研发：先读 [后端架构.md](./设计/后端架构.md)，再读对应阶段的后端设计
- 前端研发：先读 [技术调研与选型.md](./设计/技术调研与选型.md)，再读对应阶段的前端设计
- 项目管理/交付协同：优先看阶段 `README.md` 和 `开发计划.md`
- 文档治理/协作规范：先读 [文档管理规范.md](./文档管理规范.md) 和 [规范/README.md](./规范/README.md)

## 使用约定

- 新增业务内容优先判断应落在 `需求 / 设计 / 开发 / 规范` 哪一层
- 新增阶段主文档时，优先使用统一命名 `阶段需求.md`、`开发计划.md`
- 新增专题文档时，优先使用“主题 + 需求”或“主题 + 设计”的命名方式
- 修改历史文档前，先查看 [现有文档治理建议清单.md](./规范/现有文档治理建议清单.md)
