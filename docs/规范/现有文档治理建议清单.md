# 现有文档治理建议清单

## 1. 目的

本文档用于对当前 `docs` 目录中的历史文档给出低风险治理建议，帮助后续逐步完成命名收敛、主文档识别、草案归档和目录统一，而不在当前阶段直接大规模移动文件。

## 2. 总体策略

- 先补索引和元信息，再做重命名
- 先识别主文档，再处理重复表达
- 草案类文档优先标注状态，不急于删除
- 大规模迁移前，先在目录 `README.md` 中声明“当前以哪份文档为准”

## 3. 文档分类判断

当前文档大致可分为四类：

- 主文档：当前阶段最主要的需求、设计或开发依据
- 专题文档：用于展开单一问题，不替代主文档
- 草案文档：用于讨论、预研、重构分析
- 总览文档：跨阶段或跨模块的总入口

## 7. 建议优先处理的命名问题

### 7.1 同类需求文档命名不统一

当前曾混用：

- `需求拆分.md`
- `需求拆解.md`

建议目标：

- 阶段主需求统一为 `阶段需求.md`
- 专题需求统一为 `<专题名>需求.md`

### 7.2 同类设计文档命名不统一

当前混用：

- `前端设计`
- `技术设计`
- `方案设计`
- `方案`

建议目标：

- 主设计文档统一为 `总体设计.md` 或 `前端总体设计.md` / `后端总体设计.md`
- 专题设计统一为 `<专题名>设计.md`

### 7.3 开发文档存在版本漂移命名

当前曾存在：

- `单表单编辑器开发任务计划-V2.md`

试点结果与建议目标：

- 文件名统一为 `开发计划.md`
- 版本变化写入文档头部版本记录，而不是继续新增 `V3/V4`

## 8. 建议归档策略

以下情况建议迁入未来的 `docs/归档`：

- 已被主文档明确替代的旧版本
- 长期不再更新的草案
- 重命名迁移后的旧文件占位副本

归档时建议保留原路径映射记录，避免历史引用完全失效。

## 9. 推荐的下一步动作

1. 先完成核心主文档元信息补齐
2. 选一个阶段试点命名收敛，例如 `01-单表单编辑器`
3. 为重命名建立迁移清单，按“旧文件 -> 新文件”逐个执行
4. 最后再引入 `docs/归档`
