# 拖拽落点判定

## 1. 目标（二维表）
| 目标 | 说明 |
|---|---|
| 准确判定落点 | 拖拽组件到画布时，准确区分放入表单根还是某个容器 |
| 行为一致 | 编辑态与渲染态的数据结构保持一致 |
| 可扩展 | 后续支持更多容器类型与复杂嵌套 |

## 2. 可投放目标模型（二维表）
| 区域 | `droppable`类型 | 关键标识 |
|---|---|---|
| 表单根画布 | `form-root` | `type=form-root` |
| 容器组件区域 | `container` | `type=container`, `containerKey` |

## 3. 判定规则（二维表）
| 场景 | 判定逻辑 | 结果 |
|---|---|---|
| 命中容器内部，且容器允许该组件 | `over.type=container && canDrop=true` | 放入目标容器 |
| 命中容器，但容器不允许该组件 | `over.type=container && canDrop=false` | 回退根画布或拒绝投放 |
| 未命中容器，仅命中根画布 | `over.type=form-root` | 放入表单根 |
| 同时命中多个区域 | 按优先级决策 | 采用最高优先级目标 |

## 4. 落点优先级（二维表）
| 优先级 | 区域 | 说明 |
|---|---|---|
| 1 | 容器内部可投放区 | 最精确目标，优先作为落点 |
| 2 | 容器外框区域 | 容器兜底目标 |
| 3 | 表单根画布 | 全局兜底目标 |

## 5. 数据写入规则（二维表）
| 落点类型 | 数据写入 |
|---|---|
| 放入表单根 | `containerKey=null`，写入顶层 `order/index` |
| 放入容器 | `containerKey=target.containerKey`，写入容器内 `order/index` |

## 6. 视觉反馈规则（二维表）
| 状态 | 反馈 |
|---|---|
| 命中容器可投放 | 高亮容器内部投放区 |
| 命中根画布 | 高亮根画布区域 |
| 不可投放 | 显示禁止样式与提示文案 |

## 7. 实现建议（二维表）
| 项 | 建议 |
|---|---|
| 拖拽库 | 使用 dnd-kit，统一管理 `active/over` |
| 碰撞检测 | 自定义 `collisionDetection`，先筛容器内部，后回退根画布 |
| 类型校验 | `canDrop(active, over)` 统一处理组件类型兼容性 |
| 状态落库 | 统一通过 store action 更新，不在组件内直接改schema |

## 8. 示例逻辑
```ts
if (over?.data.type === 'container' && canDrop(active, over)) {
  dispatch(moveFieldToContainer({
    fieldKey,
    containerKey: over.data.containerKey,
    index,
  }))
} else {
  dispatch(moveFieldOutOfContainer({
    fieldKey,
    index,
  }))
}
```

## 9. 测试用例（二维表）
| 用例 | 操作 | 预期 |
|---|---|---|
| 根画布投放 | 拖拽字段到根画布空白区域 | 字段落入顶层，`containerKey=null` |
| 容器投放 | 拖拽字段到容器内部 | 字段进入目标容器 |
| 非法投放 | 将不支持组件拖入容器 | 禁止投放并提示 |
| 边界投放 | 拖拽到容器边框与根画布交界处 | 按优先级命中容器内部优先 |
