# 业务规则引擎

## 1. 目标与定位（二维表）
| 维度 | 内容 | 说明 |
|---|---|---|
| 文档目标 | 抽象一套服务端业务规则引擎 | 承载跨表单事务、一致性、幂等、补偿、最终校验等能力 |
| 引擎定位 | 采用流程编排式执行模型的跨表单业务事务执行引擎 | 面向订单、库存、项目管理等业务域的最终规则生效层 |
| 核心价值 | 保证业务结果最终正确落库 | 不依赖前端状态，保证事务一致性与可追溯 |
| 适用范围 | 多表单写入、资源扣减、状态推进、预算控制、跨单据联动 | 与前端交互规则引擎形成分层协同 |
| 非目标 | 不负责页面内即时联动和组件展示控制 | 这些能力由前端交互规则引擎承载 |

## 2. 系统分层与职责边界（二维表）
| 层级 | 定位 | 负责内容 | 不负责内容 |
|---|---|---|---|
| 前端交互规则引擎 | 当前表单填报交互引擎 | 当前表单内的联动、回填、筛选、汇总、提交前预校验 | 跨表单事务一致性、资源锁定、回滚补偿 |
| 服务端业务规则引擎 | 跨表单业务事务规则引擎 | 跨表单写入、业务状态推进、库存/预算扣减、幂等、事务一致性、补偿回滚 | 页面内即时交互和组件渲染 |

## 3. 适用场景（二维表）
| 业务域 | 典型场景 | 引擎职责 |
|---|---|---|
| 订单管理 | 订单提交后占用库存、生成出库单、回写订单状态 | 保证多单据状态同步与库存一致性 |
| 库存管理 | 出入库扣减、批次锁定、库存台账写入、调拨冲销 | 保证库存结果正确、幂等、可回滚 |
| 项目管理 | 工时提交流转、预算占用、任务状态推进、项目汇总更新 | 保证项目数据、预算、状态跨表单一致 |
| 财务/结算 | 单据生效后生成应收应付、核销关系、结算状态 | 保证业务单据与结算单据联动一致 |

## 4. 核心设计原则（二维表）
| 原则 | 说明 |
|---|---|
| 最终一致性优先 | 以前端体验为辅，以服务端最终裁决为准 |
| 事务封装 | 将一次业务动作涉及的跨表单变更封装为统一事务 |
| 流程编排式执行 | 每条业务规则由多个规则处理器按顺序编排执行，规则引擎本质上是服务端事务层的流程编排执行框架 |
| 幂等执行 | 相同业务请求重复提交时，不得重复扣减、重复生成数据 |
| 可补偿 | 下游步骤失败时，支持回滚或补偿操作 |
| 可裁决 | 多条业务规则命中时，需有明确优先级和冲突解决策略 |
| 可追溯 | 每次规则执行、命中、失败、补偿都可审计 |
| 与交互层解耦 | 前端只提交事实输入，服务端独立完成最终规则执行 |

## 5. 核心抽象（二维表）
| 概念 | 定义 | 作用 |
|---|---|---|
| 业务事件 | 触发服务端规则执行的业务动作 | 如“订单提交”“出库确认”“工时提交” |
| 业务规则 | 描述业务事件下的判断、校验、写入、状态推进逻辑 | 解决“业务结果如何生效” |
| 规则处理器 | 规则中的原子执行单元 | 负责校验、查询、扣减、生成单据、更新状态等 |
| 事务上下文 | 本次业务处理的输入、状态、锁、幂等键、日志等上下文 | 保证整个事务一致执行 |
| 领域资源 | 库存、预算、额度、状态配额等需被约束的业务资源 | 是强一致控制的核心对象 |
| 补偿动作 | 某步骤已成功但后续失败时，用于回滚影响的动作 | 保证失败后系统状态可恢复 |

## 6. 事件模型（二维表）
| 事件类型 | 触发时机 | 示例 |
|---|---|---|
| 单据提交事件 | 用户提交单据后 | 销售订单提交、出库单提交、工时单提交 |
| 单据状态变更事件 | 审批通过、驳回、关闭、取消 | 订单审核通过后占用库存 |
| 资源变更事件 | 库存、预算、配额变化后 | 库存扣减后刷新缺货状态 |
| 系统回调事件 | 外部系统回传结果 | ERP 创建成功后回写业务单状态 |
| 定时补偿事件 | 异步任务超时或失败后 | 释放超时锁定库存、重试回写状态 |

## 7. 规则模型（二维表）
| 属性 | 说明 |
|---|---|
| 规则ID | 规则唯一标识 |
| 规则名称 | 便于业务识别的名称 |
| 事件类型 | 由哪个业务事件触发 |
| 前置条件 | 满足哪些条件后才执行 |
| 处理器链 | 依次执行的规则处理器列表 |
| 优先级 | 多规则命中时的顺序 |
| 失败策略 | 回滚、补偿、重试、人工介入 |
| 版本信息 | 与业务模型版本、表单版本绑定 |
| 审计信息 | 创建人、更新时间、发布状态 |

## 8. 规则处理器分类（二维表）
| 处理器类型 | 作用 | 示例 |
|---|---|---|
| 查询类 | 查询业务单据、库存、预算、状态、外部数据 | 查询可用库存、查询项目预算余额 |
| 校验类 | 对输入和业务状态进行合法性校验 | 校验库存是否足够、预算是否超额 |
| 裁决类 | 多规则命中时进行优先级判断和结果裁决 | 价格策略裁决、仓库分配裁决 |
| 锁定类 | 锁定领域资源，防止并发冲突 | 锁库存批次、锁预算额度 |
| 写入类 | 写入业务结果或生成新单据 | 生成出库单、写库存台账、更新预算占用 |
| 状态推进类 | 更新主单、子单、关联单据状态 | 订单状态改为“待出库” |
| 补偿类 | 失败后撤销已执行动作 | 释放库存锁、回滚预算占用 |
| 通知类 | 发消息、写日志、触发异步任务 | 发送待办、记录规则执行日志 |

## 9. 事务上下文模型（二维表）
| 上下文项 | 说明 |
|---|---|
| 请求上下文 | 请求ID、幂等键、调用方、时间戳 |
| 业务上下文 | 当前单据、关联单据、表单版本、业务状态 |
| 资源上下文 | 库存资源、预算资源、额度资源、锁状态 |
| 规则上下文 | 当前命中规则、已执行处理器、执行结果 |
| 补偿上下文 | 已完成动作及对应补偿动作 |
| 审计上下文 | 操作人、组织、来源端、日志链路ID |

## 10. 执行链路（二维表）
| 步骤 | 说明 |
|---|---|
| 1. 接收业务事件 | 服务端接收提交、审批、回调等业务事件 |
| 2. 幂等校验 | 判断该事件是否已处理，避免重复执行 |
| 3. 构建事务上下文 | 加载业务单据、资源状态、规则配置 |
| 4. 匹配规则 | 找到当前事件下命中的业务规则 |
| 5. 执行前置校验 | 校验状态、权限、资源条件是否满足 |
| 6. 获取锁或资源占用 | 对关键资源加锁或预占 |
| 7. 顺序执行处理器链 | 完成校验、裁决、写入、状态推进等动作 |
| 8. 提交事务或触发补偿 | 全部成功则提交，失败则回滚或补偿 |
| 9. 记录日志与事件结果 | 返回处理结果，并写入审计与执行日志 |

## 11. 一致性要求（二维表）
| 一致性类型 | 要求 | 说明 |
|---|---|---|
| 单事务一致性 | 同一业务事务内多表写入必须成功或失败一致 | 如订单提交与库存占用不能只成功一半 |
| 资源一致性 | 资源占用、扣减、释放必须前后一致 | 如库存不可重复扣减 |
| 状态一致性 | 主单、子单、关联单状态需满足状态机约束 | 如出库完成后订单状态应同步更新 |
| 结果一致性 | 前端预估结果与服务端最终裁决不一致时，以服务端为准 | 提交返回最终结果给前端刷新 |

## 12. 幂等模型（二维表）
| 维度 | 需求 | 示例 |
|---|---|---|
| 幂等键 | 每次业务事件必须带唯一幂等键 | 提交单据请求ID |
| 幂等范围 | 同一业务动作重复提交只能生效一次 | 连续点击提交不会重复生成出库单 |
| 幂等结果 | 对已处理请求返回首次执行结果 | 避免重复扣减库存 |
| 幂等存储 | 服务端需保存请求结果、状态、时间戳 | 支持重试和审计 |

## 13. 锁定与并发控制（二维表）
| 控制项 | 说明 | 示例 |
|---|---|---|
| 资源锁 | 对库存、预算、额度等关键资源加锁 | 锁定物料批次库存 |
| 单据锁 | 对正在处理的业务单据加事务锁 | 防止同一订单被重复提交 |
| 行级锁 | 对单条资源记录加细粒度锁 | 锁某个项目预算科目 |
| 超时释放 | 锁超时后自动释放并记录日志 | 防止死锁和资源长期占用 |

## 14. 补偿与回滚机制（二维表）
| 场景 | 补偿动作 | 说明 |
|---|---|---|
| 库存预占成功，后续单据生成失败 | 释放库存占用 | 恢复资源可用量 |
| 预算占用成功，状态推进失败 | 回退预算占用 | 保证预算余额正确 |
| 外部系统回写失败 | 标记待重试并保留补偿入口 | 支持人工或自动重试 |
| 部分写入成功，事务整体失败 | 统一执行回滚或补偿链 | 防止半成功状态残留 |

## 15. 冲突裁决机制（二维表）
| 冲突类型 | 处理方式 |
|---|---|
| 多条规则命中同一资源 | 按优先级、业务域或生效期裁决 |
| 不同来源同时申请同一资源 | 按锁、时间戳、业务优先级裁决 |
| 外部回调与内部提交并发 | 使用状态版本号和幂等键保证结果唯一 |
| 规则升级与历史数据冲突 | 按规则版本隔离执行，历史单据沿用旧版本 |

## 16. 规则存储与发布（二维表）
| 能力 | 需求 |
|---|---|
| 规则结构化存储 | 规则需可序列化保存，支持版本管理 |
| 规则发布 | 草稿、发布、停用、回滚 |
| 规则灰度 | 支持按组织、业务域、版本灰度生效 |
| 变更审计 | 记录规则变更人、时间、差异、发布结果 |

## 17. 可观测性与审计（二维表）
| 项目 | 需求 | 验收标准 |
|---|---|---|
| 规则执行日志 | 记录事件、命中规则、处理器链、耗时、结果 | 可按请求ID或规则ID检索 |
| 幂等日志 | 记录幂等命中情况和返回结果 | 可识别重复提交场景 |
| 补偿日志 | 记录补偿触发原因、动作、结果 | 补偿链路完整可追踪 |
| 业务审计 | 记录谁在何时触发了哪次业务事务 | 满足审计追溯需求 |

## 18. 典型业务场景拆解（二维表）
| 场景 | 规则链 | 说明 |
|---|---|---|
| 销售订单提交 | 校验订单状态 -> 校验库存 -> 锁库存 -> 占用库存 -> 生成出库任务 -> 更新订单状态 | 保证订单和库存一致 |
| 出库单提交 | 校验批次与库存 -> 扣减库存 -> 写库存台账 -> 更新出库单状态 -> 回写源订单状态 | 保证真实库存结果正确 |
| 项目工时提交 | 校验成员权限 -> 校验预算余额 -> 占用预算 -> 更新任务进度 -> 更新项目汇总 | 保证工时与预算联动一致 |
| 采购入库回写 | 校验采购单状态 -> 写入库存 -> 更新采购入库状态 -> 回写采购单完成度 | 保证上下游单据状态同步 |

## 19. 与交互规则引擎的协同方式（二维表）
| 协同点 | 前端交互规则引擎 | 服务端业务规则引擎 |
|---|---|---|
| 候选项加载 | 负责 | 不负责 |
| 字段回填 | 负责当前表单内回填 | 可做最终纠偏 |
| 提交前预校验 | 负责提示和预校验 | 负责最终校验 |
| 跨表单写入 | 不负责 | 负责 |
| 状态推进 | 只做展示 | 负责最终推进 |
| 库存/预算扣减 | 可做预估提示 | 负责最终扣减 |
| 幂等与补偿 | 不负责 | 负责 |

## 20. 接口约束（二维表）
| 接口方向 | 需求 |
|---|---|
| 事件输入接口 | 统一接收业务事件，包含幂等键、业务单据标识、调用来源 |
| 规则查询接口 | 支持按事件类型、业务域、版本查询生效规则 |
| 执行结果接口 | 返回最终裁决结果、错误信息、状态变更、需前端刷新的数据 |
| 补偿接口 | 支持自动补偿、人工重试、手工回滚入口 |

## 21. MVP建议范围（二维表）
| 范围 | 建议 |
|---|---|
| P0 必做 | 业务事件接入、幂等校验、基础事务上下文、规则匹配、查询/校验/写入/状态推进处理器 |
| P0 必做 | 库存锁定与扣减、主单子单状态同步、基础补偿、规则日志 |
| P1 增强 | 预算引擎、复杂裁决、异步补偿流程编排、灰度发布、可视化流程编排 |
| P1 增强 | 跨系统回调协调、失败重放、领域模板库 |

## 22. 风险与对策（二维表）
| 风险 | 影响 | 对策 |
|---|---|---|
| 规则与事务耦合过深 | 引擎复杂度快速上升 | 分离规则定义、事务框架、领域处理器 |
| 并发控制不足 | 库存、预算等资源出现超扣 | 引入资源锁、版本号、幂等校验 |
| 补偿设计不完整 | 失败后残留脏状态 | 所有写入型处理器必须声明补偿动作 |
| 规则边界不清 | 前后端职责混乱 | 明确交互规则引擎负责体验，业务规则引擎负责最终生效 |
| 可观测性不足 | 出错时难以定位 | 建立规则执行日志、补偿日志、链路追踪 |
